<objective>
Replace the flat `customEndpoint`/`customApiKey` snapshot with a per-provider-type
`providerOverrides: { lmstudio, ollama, custom }` map (each `{ baseUrl, apiKey }`), bump the
stored envelope to `version: 2` with a pure `migrateV1ToV2` migration, and rewire
`resolveProvider` to fall back to `BUILTIN_PROVIDERS` localhost defaults when an override
`baseUrl` is empty. This is the SET-01 data-model change and the foundation Plans 02 and 03
build on. Establishes the repo's first `bun:test` files (Wave 0).

Purpose: SET-01 requires LM Studio AND Ollama addresses (and API keys) to persist across
reloads and across provider switches, encrypted-to-self, without ever leaking secrets into
persisted/devtools state. The flat single-config model cannot remember two addresses at once.

Output: v2 `ChatSettingsSnapshot` + `providerOverrides` actions in `store.ts`; envelope `version: 2`
+ `migrateV1ToV2` in `settingsStorage.ts`; updated callers in `useChatSettingsSync.ts`,
`ChatSettingsSection.tsx`, `ChatPanel.tsx`; two Wave-0 test files; a `test` script in `package.json`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Zustand store state → localStorage `persist` | Secret-bearing in-memory state (`providerOverrides[*].apiKey`) must not cross into the persisted/devtools-serialized `chat-store` blob. |
| Decrypted snapshot → `chat-store` localStorage | Only `chatSessions` + `activeChatId` may persist; settings flow exclusively through the encrypted envelope in `settingsStorage.ts`. |
| In-the-wild v1 envelope → loaded snapshot | Untrusted historical shape decrypted from localStorage; migrated by `migrateV1ToV2`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `store.ts` persist `partialize` (V8) | mitigate | Keep `partialize` allow-list = `{ chatSessions, activeChatId }` only; new `providerOverrides` (contains `apiKey`) stays OUT. Task 3 asserts the serialized partialize output contains no `apiKey`/`baseUrl` (SC-1). |
| T-01-02 | Information Disclosure | decrypted snapshot logging/devtools (V8) | mitigate | Never `console.log` the snapshot or overrides; only the encrypted envelope is written to localStorage. |
| T-01-03 | Tampering / data loss | localStorage key prefix (V6/integrity) | mitigate | Keep prefix `earthly.chat-settings.v1` stable; bump only in-envelope `version` to 2 and migrate on read (Pitfall 1) — prevents orphaning v1 envelopes (silent data loss). |
| T-01-04 | Tampering | `migrateV1ToV2` on untrusted historical payload (V5) | mitigate | Pure defensive field-by-field reconstruction with `?? default`; never trusts the decrypted shape; garbage payload yields safe defaults without throwing (Task 3 covers). |
| T-01-05 | Cryptography | encrypt-to-self envelope (V6) | accept (reuse) | No hand-rolled crypto; reuse existing `signer.nip44 ?? signer.nip04` scheme negotiation; preferred-with-fallback preserved (D-06). |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | This phase installs NO new packages (RESEARCH § Package Legitimacy Audit: none). No legitimacy checkpoint required. |
</threat_model>
