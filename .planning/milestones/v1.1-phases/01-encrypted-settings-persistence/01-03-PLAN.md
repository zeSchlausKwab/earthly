<objective>
Add the SET-03 export/import escape hatch: Export copies the current settings as plaintext JSON
(including API keys) to the clipboard with a persistent plaintext-secrets warning; Import pastes
JSON into a textarea, validates it (accepting v1 and v2 payloads, rejecting malformed/unknown/oversized),
and REPLACES current settings via `hydrateSettings` — after which the existing debounced save
re-encrypts to the current signer automatically. Pure serialize/validate helpers land in a new
`settingsExport.ts` with Wave-0 tests.

Purpose: SET-03 is the recovery path for the concrete failure mode where the OLD signer is gone
(e.g. NIP-46 rotation, or a NIP-04↔NIP-44 scheme mismatch that fails decrypt). Because the user
can no longer decrypt the old envelope, the backup must be plaintext (D-08); re-import re-encrypts
to whatever signer is now active (D-07/D-09).

Output: `src/features/chat/settingsExport.ts` (`serializeSnapshot`, `validateImportedSnapshot`),
`settingsExport.test.ts`, and Export/Import UI in `ChatSettingsSection.tsx`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pasted import JSON → store | Untrusted user-pasted text crosses into application state; must be parsed + validated before `hydrateSettings`. |
| Live snapshot → clipboard | Export deliberately emits plaintext secrets (API keys) to the OS clipboard — a known, warned-about disclosure. |
| Imported snapshot → debounced save → envelope | Re-encryption to the current signer happens via the existing save path; no new crypto. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Tampering | import: malicious/garbage pasted JSON (V5) | mitigate | `JSON.parse` in try/catch → `validateImportedSnapshot` (reject null/array/non-object, unknown `provider`, oversized payload via `MAX_IMPORT_BYTES`) before `hydrateSettings` (Pattern 4); unit-tested in Task 1. |
| T-01-11 | Information Disclosure | export: plaintext secrets on clipboard (V8) | accept (warned) | Deliberate per D-08 (recovery hatch must survive a lost signer); mitigated by a PERSISTENT user-facing warning that the clipboard holds plaintext API keys (D-10). |
| T-01-12 | Information Disclosure | export reads live store, not logs (V8) | mitigate | Serialize the in-memory snapshot directly; never `console.log` it; clipboard write is the only egress and is user-initiated + warned. |
| T-01-13 | Denial of Service (lockout recovery) | NIP-04↔NIP-44 / signer-rotation lockout (V6) | mitigate | Import re-encrypts to the CURRENT signer via the existing debounced save (D-07/D-09) — this IS the recovery path for the lockout flagged in Plan 02 (Pitfall 5). |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages this phase (RESEARCH § Package Legitimacy Audit: none). |
</threat_model>
