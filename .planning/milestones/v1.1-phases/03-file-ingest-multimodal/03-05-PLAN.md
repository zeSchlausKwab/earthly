<objective>
Register the two non-visual ingest tools in the Phase 2 typed registry: `place_dataset_features` (D-05 — apply a column-mapping rule over the FULL parsed dataset by handle, geocoding where needed, writing through the Authoring API) and `batch_geocode` (D-06 — a bounded, throttled, de-duped batch geocoder over a place-name column with skip-and-report partial failure). Single-row geocoding reuses the existing `search_location`.

Purpose: This delivers INGEST-06's two headline stories — ugly logging CSV → all points on the map, and a pasted Telegram message → one located feature. The literal acceptance bar is that placement iterates `fullRows`, never the sampled rows the model saw (anticipates SAFE-05), and routes only through the Authoring API (INFRA-02 / Phase 2 D-07 one-way Authoring API layering). Geocoding must respect Nominatim's ~1 req/s public policy.

Output: `ingest-tools.ts` (both tools + `registerIngestTools`), schemas added to `geoStaticToolSchemas`, registry bootstrap wired, and `ingest-tools.test.ts` proving full-dataset iteration + Authoring-API write + geocode bound/throttle/skip-report + coord range validation.
</objective>
