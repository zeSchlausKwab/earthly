<objective>
Build the structural privacy seam for this phase: a host-side, handle-keyed ingest store (D-11) where the model only ever receives `{handleId, summary}` and tools/sandbox read `fullRows` by handle. Derive the two summaries (compact user stat line per D-03; schema + head/tail/random sampled rows, column-capped, for the model per D-01/D-02). Auto-detect coordinate/geometry columns by name (D-04). Enforce file-size caps (D-12 discretion; V5/V12 DoS guard).

Purpose: This is the enforcement point that makes "the model never sees raw rows" a STRUCTURAL guarantee, not a convention. The model-facing accessor returns `IngestSummary` only; `fullRows` is reachable solely via `getDataset` (tools/sandbox). The store is the contract Phase 4's sandbox and Phase 5's host-side-over-full-dataset rules plug into.

Output: `datasetTypes.ts`, `ingestStore.ts`, `parseSummary.ts`, `detectCoordinateColumns.ts`, `fileSizeGuards.ts` + tests, including the no-fullRows invariant test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parsed rows → model | The single point where ingested file content could leak to the model as instructions or bulk data |
| user file → memory | Untrusted file held in the in-memory store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Information Disclosure | raw rows leaking to the model | mitigate | STRUCTURAL: `toModelSummary` is the only model-facing accessor and returns summary+handleId; `fullRows` reachable only via `getDataset`; invariant test scans the serialized model payload for non-sampled rows (Task 1/2) |
| T-03-07 | Denial of Service | huge file held in memory (multi-GB drop) | mitigate | `assertFileWithinCaps` (Task 3) rejects over-cap files before parse/hold; session-only store (D-12) bounds lifetime |
| T-03-08 | Tampering/Spoofing | CSV cell prompt-injection ("ignore previous instructions") reaching the model via sampled rows | accept | Sampled rows ARE shown to the model by design (column-mapping needs them); mitigation is framing — the summary message frames samples as DATA not instructions (enforced in Plan 05's tool-result framing). Residual risk accepted: ASVS L1, low value, no privileged action follows from a sampled cell |
| T-03-09 | Information Disclosure | wide-table token blow-up sending 80 columns to the model | mitigate | Column cap (D-02) `MAX_SUMMARY_COLS=30` + "…N more columns" (Task 2) |

T-03-08 accepted with rationale; all others mitigated. T-03-08's framing mitigation is carried into Plan 05 (tool-result message labels samples as data).
