<objective>
**THE ROADMAP-MANDATED OPENING ISOLATION SPIKE (Wave 1).** Resolve the one open design decision (QuickJS-WASM-in-a-Worker vs. cross-origin-iframe-CSP) by building the recommended transport — `quickjs-emscripten` inside a dedicated Web Worker — and proving its three acceptance criteria BEFORE any tool is wired. No `run_code` tool, no read snapshot, no UI is built here; this plan locks the isolation boundary contract that Waves 2–3 build on. Retrofitting isolation after the API is wired is a rewrite (ROADMAP Risks/Notes), so the boundary comes first.

The three spike acceptance criteria (ROADMAP / CONTEXT, non-negotiable):
- (a) Generated code provably cannot reach `localStorage`/`fetch`/DOM/signer/wallet (CODE-01).
- (b) `worker.terminate()` kills an infinite loop without freezing the host (CODE-04).
- (c) The chosen transport serves correctly under `Bun.serve()` **dev AND prod** — the residual risk is the QuickJS `.wasm` asset emitting/serving under prod `Bun.serve()` (RESEARCH Pitfall 1).

Purpose: De-risk the only greenfield element of the phase up front; everything downstream (D-01..D-14) is transport-agnostic by design and must stay so.
Output: An installed `quickjs-emscripten`, a transport-agnostic `runSandbox()` host surface backed by the QuickJS worker, the curated turf subset + output cap, and a `bun test` confinement/surface/timeout/output-cap proof. Plus a human-verified prod-serving smoke (criterion c).
</objective>
