<objective>
Stand up the `bulk-tools.ts` registrar with the two READ-ONLY tools — `select_features` (TOOLS-03 select half) and `validate_geometry` (TOOLS-04) — wired into the typed registry via the injected-register idiom, with their OpenAI schemas. Read-only means NO gate, NO snapshot, NO mutation: each reads `editor.getAllFeatures()` (the full id-keyed set, SAFE-05) and returns a structured report. This plan establishes the `registerBulkTools(register)` registrar that Plan 05 extends with the destructive tools, and proves the dev bundler does not crash on the registry edge (the Phase 2 hazard, Pitfall 4).

Purpose: Land the lowest-risk tools first (no gate complexity) so the registrar skeleton + schema + registry wiring are proven before the destructive tools build on them. select_features also gives the model the targeting feedback loop ("which features match X?") it will use before batch/style/dedup.

Output: `bulk-tools.ts` (registrar + 2 read-only handlers), 2 new schemas in `schemas.ts`, and a `registerBulkTools(register)` call in `bootstrapRegistry()`. Turns the select + validate portions of `bulk-tools.test.ts` green.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI model → tool args | select_features/validate_geometry receive untrusted predicate args; parsePredicate validates op/field/value shape (V5). |
| chat tool → editor | Tools reach editor geometry ONLY via `editor.getAllFeatures()` (read) — no write path here; the A3 boundary (mutations only through the Authoring facade) is not crossed because these tools never mutate. |
| registry ↔ bulk-tools module | A value import of `register` would form the Phase-2 circular-init cycle (Elevation/availability hazard). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04a | Tampering | Style/predicate key injection | mitigate | `parsePredicate` rejects unknown ops + malformed clauses with a catchable error (V5 input validation); the engine compares only, never executes. |
| T-06-04b | Tampering (SAFE-05) | "select all X" over the model's compacted view | mitigate | Handlers read `editor.getAllFeatures()` (full id-keyed set); schemas expose NO feature-list param (Pitfall 1). |
| T-06-04c | Denial of Service | validation over a huge dataset | accept | Read-only per-feature turf checks over the bound dataset; bounded by dataset size already held in memory; no network, no amplification. Low risk. |
| T-06-04d | Elevation (architecture) | bulk-tools breaching api/ boundary or registry cycle | mitigate | bulk-tools is in `chat/tools/` (allowed to import api/); the api/ modules it calls are boundary-clean; the registry edge is one-way (type-only import back), proven by `bun run build:production`. |
| T-06-04e | Tampering | validate_geometry mutating under guise of "report" | mitigate | Handler calls only the read-only `validateGeometryFeatures`; acceptance grep proves no mutation symbols in the read-only handlers (RESEARCH anti-pattern). |
| T-06-SC | Tampering | package installs | accept | Zero packages installed (06-RESEARCH §Standard Stack). No install task. |

No unmitigated high-severity threat.
