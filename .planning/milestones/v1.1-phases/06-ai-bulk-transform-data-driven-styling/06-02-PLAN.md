    - `matchesPredicate(feature, { all: [{field:'kind', op:'eq', value:'airport'}] })` returns true iff `feature.properties.kind === 'airport'`.
    - `op:'neq'` is the negation of `eq`.
    - `op:'exists'` is true iff the key is present AND value is not missing (A4: missing = absent OR null OR `''` OR whitespace-only string); `op:'missing'` is the exact inverse — these define fill-if-missing semantics for Plan 04.
    - `op:'contains'` does case-sensitive substring match on a string property (non-string property → false, never a throw).
    - `op:'in'` is true iff the property value is strictly one of `value[]`.
    - `op:'lt'|'lte'|'gt'|'gte'` coerce the property to a number; a non-finite/non-numeric property → false (never a throw).
    - `all: []` (empty clause list) → matches every feature (vacuous AND) so a style "fallback" can target everything; document this choice.
    - The `all` array is a flat AND — every clause must pass. No nested and/or/not trees (NOT a DSL).
    - `selectByPredicate(features, predicate)` returns EVERY matching feature in input order — the full set, never a sampled/capped subset (TOOLS-03 select half).
