<objective>
Make the Zustand store a strict one-way downstream read-mirror (D-09) and reroute EVERY remaining direct geometry write — the chat dual-write in `helpers.ts` and the 3 UI `editor.addFeature` sites in `GeoEditorView.tsx` (D-08) — through the Authoring API built in Plan 02. After this plan, `authoring.*` is the only caller of `editor.addFeature/setFeatures` outside GeoEditor core (INFRA-02), and the binding behavior-preservation golden test (criterion #2) is green.

Three precise mechanics from research/patterns (do not re-derive — implement):
1. **Close the bulk-replace emit gap (Pitfall 1):** `GeoEditor.setFeatures()` (lines 1493-1501) emits nothing, which is exactly why today's code dual-writes. Add an emit so the existing `Editor.tsx` mirror (lines 65-67) catches bulk replace, then DELETE the store-side `setFeatures` write in `importFeaturesToEditor` (helpers.ts:748).
2. **Preserve the read-mirror sink's side-effects:** `editorCoreSlice.setFeatures` (lines 21-43) does draft persistence (line 36), `isDirty:true` (39), and `updateStats()` (43). It becomes the event-driven sink — these side-effects MUST be preserved, not reduced to `set({features})`.
3. **Guard the reverse-sync loop (Pitfall 2):** `Editor.tsx:150-152` pushes store→editor on a stringify diff; with one-way mirror this can round-trip. Guard with a ref flag so Authoring-API-originated updates skip the reverse push (or narrow it to external dataset loads).

Purpose: Establish the single store-write chokepoint Phase 5's gate hooks, satisfy INFRA-02 literally (no store cross-reach), and lock criterion #2 with the golden gate.
Output: emit-on-replace, one-way mirror, dual-write removed, 3 UI sites rerouted, golden + mirror tests green.
</objective>
