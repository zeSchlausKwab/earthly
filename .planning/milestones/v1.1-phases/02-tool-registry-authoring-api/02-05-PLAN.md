<objective>
Ship the first new capability built on the Authoring API: parametric `circle` and `buffer` as Authoring API methods FIRST (D-13, in the standalone-lib layer) and registered AI tools SECOND (TOOLS-01). They wrap turf's `circle`/`buffer` (already installed, verified present, currently unused), draw immediately AND return structured `MutationResult` objects (D-11/D-15), enabling Phase 4 composition ("buffer the circle I just drew").

Binding decisions (do not re-litigate):
- **D-14 meters canonical:** methods take a numeric distance + a `units` param (default `'meters'`); the AI tool schema exposes the unit explicitly so the model states it. NO magic default radius — the caller/model MUST specify (validation rejects missing/non-finite radius).
- **D-15 buffer targets by feature id primarily** (`buffer(featureId, distance)` — resolves via `editor.getFeature(id)`, composes with returned ids per D-11) AND also accepts raw GeoJSON geometry for programmatic/sandbox use. Circle is center + radius.
- **turf `buffer` can return `undefined`** for degenerate/empty input — the Authoring API MUST null-check and return `{ ok:false }` / feed a `ToolError`, never crash (D-16 coupling).
- **Security (V5):** bound circle/buffer radius — reject NaN/Infinity/negative/zero and absurdly large values that would freeze the main thread on turf step generation.

Purpose: Satisfy TOOLS-01 + ROADMAP criterion #4 (AI draws a parametric circle and a buffer around a feature; same primitives callable as direct API methods).
Output: `primitives.ts` (turf wrappers) + `authoring.circle/buffer` methods + `draw_circle`/`buffer_feature` registered tools; primitive + registry-integration tests green.
</objective>
