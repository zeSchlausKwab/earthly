<objective>
Build the Authoring API: the single, pure, AI-agnostic, framework-agnostic geometry-mutation facade (`src/features/geo-editor/api/`) that becomes the only path mutating editor geometry (INFRA-02). This is the load-bearing seam Phases 3–7 route through.

Hard architectural constraint (D-07): `api/` has ZERO imports from chat, the tool registry, or Nostr — it must be shippable as a standalone editor library. A boundary test enforces this.

This plan delivers the facade's geometry write methods (`addFeature`, `writeGeoJSON` for both replace and append) reimplemented on top of GeoEditor with NO behavior change — they CALL the existing `toEditorFeature()` and reuse the dedup-by-id logic verbatim (Pitfall 4: reimplementing normalization breaks the binding criterion #2). Every mutating method returns a structured `MutationResult` (D-11), never void. It also scaffolds the interceptor/middleware pipeline + intent enum (`add | modify | delete`, D-12) so Phase 5's safe-editing gate drops in without restructuring — but builds NONE of Phase 5's diff/preview UI, safety persistence, or undo.

This plan does NOT yet remove the chat/UI dual-writes or wire the store mirror — that is Plan 03, which depends on this facade existing.

Purpose: Create the standalone geometry seam + result contract + gate scaffold that the store-mirror reroute (03), the registry (04), and the primitives (05) all build on.
Output: `api/{results,interceptor,authoring,index}.ts` + boundary test (green) + an authoring unit test exercising add/write/replace/append on the headless editor.
</objective>
