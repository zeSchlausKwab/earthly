<objective>
Collapse the two ad-hoc tool-dispatch systems — the 24-case `switch` in `execute.ts` (lines 173-787) and the separate `editor_*` registry in `commands.ts` — into ONE unified typed registry (D-01) where each entry co-locates its OpenAI-function schema, its handler, and mandatory `kind` metadata (D-03). Migrate all ~30 tools this phase (D-02). The registry is dynamic (`register`/`unregister`, D-04); the model's advertised tool list is derived from live registry state with serialization decoupled from dispatch (D-06). Replace the bare `throw` at `execute.ts:786` with the unified structured `ToolError` contract (D-16) covering both unknown-tool-name and handler-runtime-failure — fed back into the model loop AND surfaced distinctly in the chat UI.

Geometry-mutating tools (`add_feature_to_editor`, `write_geojson_to_editor`, editor commands) dispatch INTO the Authoring API built in Plans 02/03 — the registry never touches `editor.*` directly. `kind` mapping (Pitfall 5): OSM/valhalla/web/wiki/fetch → `remote-mcp` (origin = `EarthlyGeoServerClient.SERVER_PUBKEY`); editor reads/writes + host snapshot/context → `host-builtin`/`editor`; `editor_*` → `editor`.

Purpose: Satisfy INFRA-01 (single typed dispatch, unknown = hard error) and set the self-correction error pattern Phase 4's sandbox plugs into.
Output: `registry.ts` + `errors.ts` (new), `execute.ts` switch → `registry.dispatch`, `definitions.ts` static → derived, `commands.ts` self-register, `ChatPanel.tsx` MessageBubble renders ToolError; registry/errors/commands tests green.
</objective>

| Boundary | Description |
|----------|-------------|
| model (LLM) → registry.dispatch | LLM-chosen tool name + raw JSON args (untrusted) cross here. The single dispatch chokepoint. |
| remote-mcp handler → ContextVM/Nostr | Remote tool calls leave the host; failures must be attributed (origin). |
| registry result/error → chat UI | Serialized tool output/error rendered to the user. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Tampering / Repudiation | LLM emits unknown/garbage tool name → silent no-op masks failure | mitigate (HIGH) | D-16: unknown name → `ToolError(unknown_tool)` fed to the model loop AND surfaced in UI (replaces the bare throw at execute.ts:786). This is a security control, not just UX — asserted in `registry.test.ts`. Block on red. |
| T-02-11 | Denial of Service | malformed/oversized LLM JSON args (huge coordinate arrays, truncated JSON) | mitigate (HIGH) | Reuse battle-tested `parseToolCallArguments` (truncation repair) + numeric clamps + `MAX_GEOJSON_TEXT_CHARS` cap at the dispatch input boundary (V5). Do NOT introduce zod into the hot path (regression risk). |
