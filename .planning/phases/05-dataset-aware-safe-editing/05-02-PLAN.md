<objective>
Build the dataset-level snapshot/undo stack (SAFE-06) and close the uncapped recorded-call write channel (WR-04) — the two editor-core/sandbox mechanisms the safe-editing gate relies on for reversibility and DoS resistance.

Purpose: SAFE-06 requires AI dataset edits — including property, style, translation, and metadata changes, not just geometry — to be reversible via a dataset-level snapshot/undo, with one undo step per confirmed apply (D-10/D-11). The existing `HistoryManager` is geometry-only and carries no `CollectionMeta`, which is exactly why D-10 mandates a SEPARATE stack. Separately, the Phase-4 review's WR-04 left the recorded-authoring write channel uncapped — this phase owns that seam and must bound it.

Output: a `DatasetSnapshotManager` mirroring `HistoryManager`'s class shape but holding `{ features, collectionMeta, label, timestamp }` entries with a bounded depth and reference (not deep-clone) storage; `GeoEditor.undo()` consults it first; and a recorded-call count + serialized-byte cap at the sandbox worker, rejected before the synchronous host replay.

This plan touches editor-core and sandbox files only — no chat-UI, no `api/` overlap with Plan 01.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted sandbox code → worker recorded-call channel | Sandbox JS can call `authoring.*` arbitrarily; the worker records each call. Uncapped, this is a write-path DoS (WR-04). |
| Worker → host synchronous replay | The host replays recorded calls synchronously on the main thread; an unbounded batch freezes the app even though each individual op is allow-listed. |
| Editor state → snapshot stack | Snapshots hold references to feature objects + metadata; an unbounded stack is a memory-exhaustion vector (the Phase-4 OOM class). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06 (WR-04) | Denial of Service | `recordedCalls` recording loop in `sandbox.worker.ts` | mitigate | Task 3 caps recorded-call count + total serialized arg bytes at the worker (mirroring the console cap) and rejects over-budget batches before the host replay loop. |
| T-05-07 | Denial of Service (memory) | `DatasetSnapshotManager` stack | mitigate | Task 1 bounds depth to ~10-20 and stores references + a structural array copy, never a deep coordinate clone (Pitfall 3 / A1). |
| T-05-08 | Tampering (silent partial apply) | host replay of an over-budget batch | mitigate | Task 3 rejects the WHOLE batch before any replay — no partial geometry write; surfaces a model-facing ToolError. |
| T-05-09 | Tampering / Repudiation | AI dataset edit not reversible (incl. metadata) | mitigate | Task 1+2 make every gated AI apply reversible via a metadata-aware snapshot/undo, one step per apply (SAFE-06 / D-10/D-11). |
| T-05-10 | Elevation of Privilege | new verbs reaching the sandbox replay surface | accept | Per decision A5, modify/delete are NOT added to `AUTHORING_METHODS`/`REPLAYABLE_AUTHORING_OPS` this phase — host-tool-only; CR-01 allow-list invariant unchanged. |
</threat_model>
