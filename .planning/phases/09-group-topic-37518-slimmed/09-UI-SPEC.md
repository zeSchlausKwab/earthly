# Phase 9 — UI Design Contract

> Visual and interaction contract for the Group / Topic (37518 slimmed) frontend surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance posture:** This phase REFACTORS existing panels (`MapContextEditorPanel` → `GroupEditorPanel`, `MapContextViewPanel` → `GroupViewPanel`). Spacing, color, and typography are **inherited from the shipped app design system** (`styles/globals.css` oklch tokens, Poppins, the `EntityPanelShell` / `EntityPanelSurface` / `EntityPanelSectionHeader` primitives, the `rounded-none` convention). This contract expresses only the deltas the governance-ladder / NO-MOD-MINIMUM surfaces add — it does NOT invent a new look & feel.

## Spacing Scale

The app's base unit is **4px** (`--spacing: 0.25rem`). Panels are dense (`text-[13px]` bodies, `py-2` rows). Declared scale (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|--------------------|
| 2xs | 4px | Inline chip padding (`py-0.5`), icon-to-label gaps (`gap-1`), eyebrow-to-title gap |
| xs | 8px | Compact element spacing (`gap-2`, `space-y-2`); list-row vertical padding (`py-2`); chip horizontal padding (`px-2`) |
| sm | 12px | Section inner stack (`space-y-3`); surface inner padding (`px-3 py-3` on discussion tone) |
| md | 16px | Discussion / comments block stack (`space-y-4`); governance radio-card internal padding |
| lg | 24px | Gap between major editor sections when expanded |
| xl | 32px | Reserved — not needed inside the panel column (panels are width-constrained) |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

**Exceptions:**
- Interactive icon-only controls (⋮ overflow trigger, EntityActionBar buttons, eye/zoom) render at the existing `h-6`/`h-7` (24–28px) compact panel sizes — these are inside a desktop side panel, not primary touch targets. On the mobile collapsible-panel breakpoint, the ⋮ overflow trigger and lock-down button MUST present a **≥44px** hit area (pad the trigger; icon stays 14–16px).
- Schema-builder property rows keep the existing `px-3 py-2` bordered-row rhythm from `MapContextEditorPanel` — do not widen.

## Typography

Inherited from `EntityPanelShell` + the panels. Poppins throughout; JetBrains Mono only for raw JSON and nostr coordinates. Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Display (panel title) | 20px (`text-xl`) | 600 (semibold), tracking `-0.03em` | 1.2 | `GroupEditorPanel` / `GroupViewPanel` top title via `EntityPanelShell` |
| Heading (section title) | 14px (`text-sm`) | 600 (semibold), tracking `-0.02em` | 1.3 | `EntityPanelSectionHeader` titles; governance card title |
| Body | 13px (`text-[13px]`) / 12px (`text-xs`) | 400 (regular) | 1.5 (`leading-5`) | Descriptions, contributor explanations, list-row primary text (12px medium), narrative |
| Label / meta | 11px (`text-[11px]`) / 10px (`text-[10px]`) | 400, eyebrows 600 uppercase tracking `0.2em` | 1.4 | Field labels, chip text, filter-reason, eyebrows, coordinate strings |

**Weights:** regular (400) and semibold (600) only — matches the codebase. No medium/bold elsewhere; "medium" rows in legacy code (`font-medium` = 500) are tolerated as inherited but new copy uses 400/600.

**Monospace:** raw-JSON advanced tab `Textarea` and any rendered `c`/`a` coordinate use `font-mono text-xs` (existing convention).

## Color

Inherited oklch tokens (`styles/globals.css`). Light + dark both defined; use **semantic tokens only** (`bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `border-border`, `bg-primary`, `bg-destructive`) — never raw `dark:` variants for semantic color.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` (near-white light / near-black dark) + `.glass-panel` surface | Panel canvas, surface backgrounds, list rows |
| Secondary (30%) | `--muted` / `--muted-foreground` / `--border` (neutral greys) | Section dividers, chip borders, meta text, disabled controls, the **subordinate foreign lane** chrome |
| Accent (10%) | `--primary` (warm amber/gold `oklch(0.85 0.17 88)`) | Reserved list below |
| Secondary semantic | `--secondary` (cyan/blue `oklch(0.75 0.16 233)`) | The privileged CURATED lane accent ONLY (see below) |
| Destructive | `--destructive` (red) | Lock-down → closed confirm action; delete-Group; never for warnings |

**Accent (`--primary`) reserved EXCLUSIVELY for:**
1. The selected governance radio-card ring/fill (D-01) — the one active choice.
2. The primary submit button of the editor ("Create Group" / "Save Group") and the contributor "Publish anyway" button (D-06).
3. The active state of the per-view filter control's selected segment (D-09).
Nothing else. Section eyebrows, meta, counts, and inactive controls stay neutral (`muted-foreground`).

**Two-lane color encoding (NO-MOD trust posture — D-07/D-08, load-bearing):**
- **Curated lane** = privileged. Render with the `context`/`secondary` tone: `EntityPanelSurface tone="context"` (amber-bordered) header + full-strength `text-foreground` rows, expanded by default. A "Canonical" badge uses `--secondary` (`variant="secondary"`).
- **Foreign lane** = subordinate. Render in `tone="neutral"` (grey), inside a **collapsed** `Collapsible` titled "Community contributions (N)", rows at `text-muted-foreground`. It must read visually quieter than the curated lane. NEVER give the foreign lane an accent color or co-equal tab.

**Validation / governance status colors (chips & inline warnings):**
- Conforming / valid → `--secondary` or emerald-on-neutral chip (existing `bg-emerald-100 text-emerald-700` pattern is acceptable inherited usage).
- Non-conforming / warn → amber chip + `Alert` `variant="default"` with an amber left accent (NOT destructive — a warning is never an error here). Inherited `text-amber-700` pattern.
- Filtered-out reason → neutral `Badge variant="outline"` with the reason text.
- Schema-hash mismatch / unverifiable schema → amber warning, copy: "Schema could not be verified" (treated as warn, never silently strict-hides).
- Signature/kind validation failure → item is **dropped before render** (no chip; it never appears — GROUP-08).

Dark-mode parity: every chip/badge/alert MUST use token-driven classes so the dark palette (already defined in `globals.css`) applies automatically. Avoid hard-coded `text-slate-900` for new copy; prefer `text-foreground` / `text-muted-foreground`. (Legacy `slate-*` literals in the refactored files may be migrated opportunistically but are not a blocker.)

### Error / warning states

| Situation | Copy (problem → what to do) |
|-----------|------------------------------|
| Group name missing (editor) | Group name is required. |
| Invalid raw-JSON schema (advanced tab) | Schema JSON is invalid: {parser message}. Fix it or switch back to the builder. |
| External `$ref` in schema | External references aren't allowed. Use a self-contained schema. |

| Publish failed (network/sign) | Couldn't publish — check your connection and try again. |

| Schema couldn't be fetched/validated off-thread | Couldn't check this contribution right now. It's shown unfiltered. |
| Per-item filter reason chip (warn mode) | e.g. "Hidden: missing required `name`" / "Hidden: geometry `Polygon` not allowed". |

## Interaction Contracts (phase-specific surfaces)

These are the load-bearing interaction specs the executor implements. Each cites its decision.

### 1. Governance ladder (D-01) — `GroupEditorPanel`
- 3 `RadioGroup` items rendered as `Card`-bodied radio cards in a vertical stack (single column in the narrow panel). Each card: title (14px semibold) + one-line explanation (12px `muted-foreground`) from the copy table.
- Selected card: `--primary` ring + subtle accent fill; unselected: `border-border`, neutral.
- The schema-authoring section (item 2) is **conditionally mounted** only when `schema` is selected (mirror the existing `allowForeignAttachments &&` gating, but keyed on `governance === 'schema'`). Leaving `schema` strips `geometryConstraints`/`schema` from content per O-02.

### 2. Schema visual field-rule builder (D-04) — `GroupEditorPanel`
- A `Tabs` with **Builder** (default) and **Advanced (JSON)** triggers (reuse the existing tab-trigger styling: `h-8 rounded-none border-b-2`).
- **Builder:** vertically stacked bordered property rows (`border border-border px-3 py-2`, `space-y-2`), each row containing: `Input` (property name) + `Select` (type: text/number/integer/boolean/enum) on one line; for `enum` reveal an allowed-values `Input` (comma-separated) on a second line; a `required?` `Checkbox`; a ghost **Remove** button (`h-6`). Below the rows: an outline **Add property** button. Separate from property rows: a **geometry-type checkbox set** (`grid grid-cols-2 gap-2`) over `MAP_CONTEXT_GEOMETRY_TYPES`.
  - **Bug to fix from legacy:** the old builder's `required` toggle used a raw `<Input type="checkbox">` and the geometry checkboxes used a bare unstyled `@radix-ui/react-checkbox` with no label association (`MapContextEditorPanel.tsx:900-913`). Use the shadcn `Checkbox` + `Label htmlFor` pairing so each control is labeled and keyboard-reachable.
  - Empty state when no rows: the inline copy from the empty-states table.
- **Advanced (JSON):** `Textarea` `font-mono text-xs` rows≥12; live parse error surfaced inline (error copy table). Both tabs compile to the same draft-2020-12 schema fed to the Phase-8 `validateSchema()` worker.
- Keep the existing "Sample properties JSON" live-validation affordance (valid=secondary/emerald, invalid=amber, parse-error=destructive) — it is good adoption UX.

### 3. Contributor attach + inline warnings (D-05/D-06) — contributor's dataset publish/edit dialog
- A **"Attach to a Group"** picker (reuse `EntitySearchPopover` / `command` + `popover`) that writes the `c` tag on the 37515 dataset.
- For a `schema` Group: on selection, run off-thread validation; render results as an **`Alert`** block (amber, NOT destructive) listing per-rule failures, each line specific and dismissible. A prominent accent **Publish anyway** button sits beside the normal publish. **Hard invariant:** warnings never disable publish; a standalone-valid dataset always publishes (GROUP-04).
- While validating: a small inline `Spinner` + "Checking against {Group name}'s rules…". On worker failure: the "couldn't check" warn copy, publish still enabled.

### 4. Two-lane view (D-07/D-08) — `GroupViewPanel`
- **Curated lane** (`tone="context"`, expanded, privileged): "Canonical references" `EntityPanelSectionHeader` + rows with full `text-foreground`, each row an `EntityActionBar` (Inspect / Zoom). A "Canonical" `Badge variant="secondary"`.
- **Foreign lane** (`tone="neutral"`, **collapsed** `Collapsible`): trigger reads "Community contributions (N)"; body lists ≤**50** rows, **newest-first** (RESEARCH O-01 / A1: no trust-sort source exists this phase — ship recency only; follows-boost is a documented follow-up), then a **Load more** button. Rows at `text-muted-foreground`, visually quieter than curated.
- "Canon first, contributions second" must be unmistakable: curated is above, amber-toned, open; foreign is below, grey, closed-by-default. No co-equal tabs (anti-pattern per RESEARCH).

### 5. NO-MOD affordances (GROUP-08)
- **Owner escape hatch (D-02):** a visible owner-only button on the view panel header area — "Lock down → Closed", destructive-toned. Opens the `alert-dialog` (confirm copy above); on confirm, `GroupFactory.modify(governance:'closed')` + republish. Reachable the instant abuse is seen — never buried in the edit form.
- **Curated pinning two ways (D-03):** (a) on each foreign-lane row, an owner-only **Add to curated** button ("bless"); (b) in the editor, an **Add curated reference** search picker. Both append to the Group's `a` refs.
- **Per-view filter (D-09):** an Off/Warn/Strict segmented control (use `tabs` or `toggle-group`) attached to the foreign lane, **default Strict**. Strict hides non-conforming; Warn shows them with an amber badge + legible per-item reason chip; Off shows all. Every hidden/flagged item carries a legible reason (copy table).
- **Per-attachment mute (D-12):** a `dropdown-menu` ⋮ overflow on each foreign-lane row → "Mute @{name}" (+ Inspect / Zoom). Muting is instant, device-local (D-10), global (D-11) — muted authors drop from the lane app-wide; confirm via undo-able `sonner` toast.
- **Pre-render validation (GROUP-08):** every `c` coordinate is signature- and kind-validated and mute-filtered BEFORE it is rendered as a row — invalid items never paint (no chip, no flash).

## Responsiveness & Accessibility

- **Mobile-first / collapsible panels** (per CLAUDE.md): the Group panels live in the existing collapsible side-panel system. The two-lane layout stays single-column at all widths (it already is). On small screens the ⋮ overflow trigger and the lock-down button get a ≥44px hit area.
- **Keyboard:** governance radio cards are a real `RadioGroup` (arrow-key navigable); schema rows, checkboxes, and the ⋮ menu are all keyboard-reachable with visible focus rings (`outline-ring/50`, already global). Fixes the legacy unlabeled-checkbox a11y gap (item 2).
- **Reduced motion:** Collapsible/Alert/Dialog animations respect the global `@media (prefers-reduced-motion)` rule already in `index.css`.
- **Color is never the only signal:** non-conforming items carry a text reason chip, not just an amber hue; the active governance card shows a selected radio dot, not only an accent ring.
- **Markdown narrative (GROUP-06):** rendered through the app's existing sanitized `RichContentRenderer` (no raw HTML — XSS posture matches Story/NIP-23).
