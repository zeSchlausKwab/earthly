| Boundary | Description |
|----------|-------------|
| client → provider | Vision detection fetches only the configured provider baseUrl (`/api/show`, `/v1/models`) — never a URL derived from file content |
| model selection → image send | The decision point for whether an image leaves the client toward the model |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Information Disclosure / Spoofing | image silently sent to a non-vision (blind) model | mitigate | D-07 fail-safe to `'no-vision'` on unknown/unreachable + D-08 (Plan 06 UI hard-disable/opt-in); the autonomous snapshot path sends only on confirmed `'vision'` (Task 2). Acceptance criterion #4 |
| T-03-11 | Server-Side Request Forgery | vision detection fetch target | mitigate | Fetch URL is always `provider.baseUrl` + a fixed path (`/api/show` or `/models`), never a value derived from file content or model output (Task 1) |
| T-03-12 | Denial of Service | repeated `/api/show` network calls per send | mitigate | Per-`(type,baseUrl,modelId)` cache (Task 1); detection resolved once per request |
| T-03-13 | Denial of Service | Ollama down / CORS blocks `/api/show` | mitigate | Catch → degrade to name heuristic → `'uncertain'`, never throw (Task 1); request loop unaffected |

All threats mitigated. The user-facing three-tier UI (D-08) is built in Plan 06 and consumes this same ladder.
