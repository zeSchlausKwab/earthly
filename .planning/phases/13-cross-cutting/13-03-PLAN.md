<objective>
The real body of Phase 13: make Live Beacons (37521) and Temporal Sightings
(37522) first-class Map Stack citizens so the app's core invariant — "what's on the
Map Stack is visible" — holds for EVERY entity type, and DELETE the `66a155e`
`extraMapBeacons` side-channel hack (D-01, SPEC §1/§3.5). Today `useMapLayers`
renders `useSightings()`/`useBeacons()` unconditionally, bypassing the stack. This
plan routes them through stack-derived selectors that mirror `visibleGeoEvents`,
reusing the shipped `isolated` machinery for deep-link-solo (D-03).

Purpose: Close v1.2 with a coherent map-visibility model and pay down the debt
Phase 12 created (the `66a155e` hack). Advances ROADMAP SC-2 (addressable/openable
entities) and the folded-in unification (D-01), and satisfies the Deferred Item
"SIGHT-02 Group-lane rendering / on-stack rendering" for sightings/beacons.
Output: Stack-gated sighting/beacon rendering; deep-link-solo; hack deleted.

CRITICAL RISK CONTROL: `useMapLayers` is the SHARED render path for datasets/
contexts. This plan does NOT edit useMapLayers' body — `visibleSightings`/
`visibleBeacons` are ALREADY props (L448-451, default []); the change is
CALLER-SIDE ONLY (GeoEditorView passes stack-derived sets). `buildSightingSource`
(~L271) / `buildBeaconSource` (~L360) with their internal `dropExpired` +
freshest-per-`{pubkey,d}` de-dup stay byte-for-byte. `visibleGeoEvents` handling
inside the hook is untouched.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay subscription → stack-gated render | untrusted sighting/beacon events flow through the stack selectors to the map |
| route (untrusted) → isolated stack entry | a crafted deep-link creates an isolated:true stack entry |
| beacon geometry → map render (Phase 12 CR-01/CR-02) | beacon position rendering must not regress the GPS-privacy posture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-03-FORCEISO | Tampering | route → addMapStackEntry({isolated:true}) | mitigate | A crafted route can only isolate the SINGLE entity the naddr resolves to (entityKey = that naddr/dTag) — it cannot isolate or inject an arbitrary OTHER layer, because addSightingToMapStack/addBeaconToMapStack derive entityKey from the resolved entity, not from raw URL fields. The existing setMapStackEntryIsolated rule is mutually-exclusive (suppresses, never elevates). Acceptance: Task-1 isolation test proves an isolated entry renders ONLY its own entity; the route handler passes the resolved entity, not URL-supplied keys. |
| T-13-03-DROPEXPIRED | Information Disclosure / Integrity | stale/expired beacon still painted | mitigate | Do NOT bypass the source-builder filters: buildSightingSource/buildBeaconSource keep their internal dropExpired (useMapLayers L273/L362) — the stack selectors feed them an input set but never a pre-built source, so an expired entity still gets dropped at build time. Acceptance: `git diff` shows useMapLayers.ts unchanged (dropExpired intact); the empty-stack → [] test + the aggregate → full-set-then-dropExpired path preserved. |
| T-13-03-GPSREGRESS | Information Disclosure | beacon GPS-privacy (Phase 12 CR-01/CR-02) | mitigate | The unification changes WHICH beacons render (stack membership), not HOW a beacon's position is rendered. buildBeaconSource + the link-only discovery gating (Phase 12 P-6: link-only beacons omit t:live/g/bbox and never enter the #t:['live'] subscription) are untouched. A link-only beacon still only renders when explicitly deep-linked/added (isolated 'route' entry), NOT via the aggregate layer. Acceptance: useBeacons #t:['live'] discovery filter unchanged; useMapLayers.ts unchanged; the individual-pin test proves a beacon renders only when its entry exists. |
| T-13-03-REGRESSION | Denial of Service (self-inflicted) | shared useMapLayers dataset/context render path | mitigate | The dataset/context path via visibleGeoEvents is the flagged highest-risk seam. Mitigation: no edit to useMapLayers.ts and no edit to visibleGeoEvents; only the two NEW props change caller-side. Acceptance: `git diff --stat useMapLayers.ts` empty; full-suite regression (bun test) shows no new dataset/context/map test failures. |
</threat_model>
