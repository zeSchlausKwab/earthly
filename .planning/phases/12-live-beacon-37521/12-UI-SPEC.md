# Phase 12 — UI Design Contract

> Visual and interaction contract for Live Beacon (kind 37521) authoring + live-map-render UX. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance posture:** Earthly is an EXISTING app with a locked design system. This phase MIRRORS the Phase-10 Story / Phase-11 Sighting spine (browse rail → info-panel view/control → distinct map marker → deep-link + OG card) and reuses the existing map-layer + `watchPosition` machinery. It does NOT introduce a new design language. All spacing/typography/color below are declared BY REFERENCE to the established `styles/globals.css` oklch tokens and the shipped Phase-9/10/11 panel components, not invented.
>
> **Net-new surfaces requiring concrete specs (the rest is reuse):**
> 1. The **running-beacon status surface** — a persistent, glanceable "you are live" banner/pill with last-seen age, countdown, and one-tap Stop (mobile-critical, no Phase 10/11 twin).
> 2. The **Start-beacon authoring control** — time-box presets + visibility choice + identity choice + the no-delete consent.
> 3. The **live / stale / ended beacon map marker** — distinct from a Sighting (which is observation, not live presence) and from a dataset dot.
> 4. The **link-only "unlisted, not encrypted" honesty caveat** — a non-dismissible-by-accident inline disclosure.
>
> **MOBILE IS THE PRIMARY DEVICE FOR THIS PHASE.** A live position beacon is used in motion, phone in hand, outdoors, foreground-only. Every control below specifies mobile behavior FIRST; desktop is the wider-viewport variant. Start/Stop are safety-relevant controls — large, unambiguous, thumb-reachable.

## Spacing Scale

Earthly's Tailwind v4 base unit is `--spacing: 0.25rem` (4px), so the standard 4-point scale applies. **Project standard-set override (deliberate, documented, inherited from Phase 9/10/11):** the panel surface rhythm is **12px** (`px-3 py-3` / `space-y-3`) to match the already-shipped `EntityPanelShell` chrome — a multiple of 4, kept at 12px (not 16px) to preserve visual continuity with the shipped entity panels.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `gap-1` / `p-1` | Icon-to-label gaps, badge inner padding, status-chip padding, last-seen-age chip |
| sm | 8px | `gap-2` / `p-2` | Compact form-field spacing, marker label offset, browse-row inner gaps, banner inner gaps |
| md | 12px | `gap-3` / `p-3` | Panel surface padding (matches `EntityPanelSurface`), section spacing (`space-y-3`), running-beacon banner padding |
| lg | 16px | `gap-4` / `p-4` | Control-panel form section spacing (`space-y-4`), preset-grid gaps |
| xl | 24px | `gap-6` | Major section breaks within a panel (time-box ↔ visibility ↔ identity) |
| 2xl | 32px | `gap-8` | Empty-state vertical centering |

**Exceptions (mobile-critical — NOT optional):**
- **Start / Stop are ≥ 48px tall touch targets** (`h-12`, exceeds the 44px floor). These are safety-relevant controls used one-handed in motion; they must be hard to mis-tap. Desktop may render them at the standard `h-9`/`h-10`; **mobile renders them at `h-12` minimum**, full panel width.
- **Running-beacon banner Stop hit area ≥ 44px** even when the banner is a compact pill — the Stop affordance inside the always-visible banner must be one unmistakable tap.
- **Beacon map-marker hit target ≥ 44px** square for touch (an invisible padded layer; the visible glyph is smaller), so a finger over a small-zoom map can still select it.
- **Time-box preset chips ≥ 44px** tall on mobile (`min-h-11`), laid out as a 2×2 grid (not a cramped single row) so "15 min / 1 hr / 4 hr / 8 hr" each get a full thumb target.
- Panel surface padding stays at 12px (`px-3 py-3`) per the documented inherited override.

## Color

Earthly's oklch tokens (`styles/globals.css`). Use **semantic tokens only** — never raw hex for new chrome (the map-marker layer is the one place concrete hex is used, mirroring the shipped Sighting layer constants in `useMapLayers.ts`). The 60/30/10 split maps to existing tokens.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` + `--panel-bg` (`.glass-panel` translucent) | Map canvas, info-panel surfaces, browse-panel background, control-panel form fields, running-beacon banner surface |
| Secondary (30%) | `--sidebar` / `--muted` / `--secondary` (blue `oklch(0.748 0.155 233)`) | Left rail, card/row backgrounds, subordinate chips, the link-only visibility chip tint |
| Accent (10%) | `--primary` (warm amber/gold `oklch(0.854 0.174 89)`) | RESERVED — see list below |
| Destructive | `--destructive` (red `oklch(0.583 0.239 28)`) | The **Stop sharing** action + the no-delete consent's emphasis only |

**Accent (`--primary`) reserved EXCLUSIVELY for:**
1. The **"Share live location"** / **"Start beacon"** primary button (top of the Beacons browse panel + the rail New action + the control panel's Start submit).
2. The **selected-state ring** on the chosen **time-box preset** and the chosen **visibility option**.
3. The **live beacon map marker** — a beacon currently within its staleness window renders with the `--primary` solid fill + ring. This is THE focal point on the canvas (see Net-New §3): "someone is here, right now."

Accent is NEVER used for: ordinary links, all interactive elements generally, the Stop button (Stop is destructive-toned — it ends a live session), stale/ended markers, the share-link copy button, comment/react actions, or section headers.

**Stop is destructive-toned, NOT accent.** Stop ends a live presence and leaves a permanent last point on a no-delete substrate (D-04/D-06) — it carries the `--destructive` tone (not a hard red alarm, but the destructive variant) so it reads as consequential, never as the cheerful primary action. Start is the accent; Stop is destructive.

**Beacon lifecycle visual states (D-07/D-08 — net-new). Map-marker hex mirrors the shipped Sighting layer constants:**

| State | Definition | Marker treatment | Status chip |
|-------|-----------|------------------|-------------|
| **Live** | `now − created_at` < staleness threshold AND `status==='live'` AND not expired | Solid `--primary` fill (`#fdc700`), full opacity, `--primary` ring + a soft pulse halo (reduced-motion: static ring) | "LIVE" pill, `--primary` bg, 12px semibold, + "last seen now / Ns ago" |
| **Stale** | `now − created_at` ≥ staleness threshold AND `status==='live'` AND not expired | **Greyed-out** fill `#737373` (`--muted-foreground`, the shipped Sighting "past" hex), 70% opacity, NO ring, NO pulse — visibly demoted but still placed | "STALE" pill, `--muted-foreground` bg, + "last seen 4 min ago" (honest age preserved — BEACON-03) |
| **Ended** | `status==='ended'` (explicit Stop, D-04) AND not expired | Distinct **hollow** marker: `#737373` outline ring, transparent fill, a small "■"/stop glyph — clearly terminal, NOT a faded-live and NOT a network drop | "ENDED" pill, `--muted-foreground` bg, + "ended Nm ago" |
| **Removed** | `isExpired` (past NIP-40 `expiration`) | Marker REMOVED entirely by `dropExpired` at every read path (BEACON-03) — never merely hidden | — (gone) |

Greyscale ramp: live = full-color accent; stale = neutral grey at 70% opacity; ended = neutral grey outline only. The transition live→stale is a **single discrete step at the threshold** (not a continuous fade) so "is this current?" is unambiguous at a glance on a small screen.

**Three coexisting clocks — legible, not equal-weight raw fields (D-03/D-04/D-07/D-08):**
- `created_at` → drives the **last-seen age** ("last seen 2 min ago") and the live/stale step. Surfaced as friendly relative age, never as a raw epoch.
- NIP-40 `expiration` → drives **removal** and the **time-box countdown** ("ends in 38 min"). Surfaced as a countdown, never as a raw date.
- user-set **time box** → sets `expiration` at Start via a friendly preset. Never shown again as a raw field after Start.

### Error / permission states (D-discretion — geolocation handling)

| Situation | Copy (problem → what to do) |
|-----------|------------------------------|
| Location permission denied at Start | "Earthly needs location access to share a beacon. Turn it on in your browser settings, then try again." (Start stays disabled until granted) |
| Location unavailable / no fix mid-session | "Can't get your location right now. Your beacon will pick back up when your signal returns." (banner shows a "searching…" sub-state; the marker goes **stale** honestly, not frozen-as-live) |
| Publish failed (network) | "Couldn't update your beacon. Check your connection — it'll retry automatically." |

### Destructive / high-stakes confirmation

| Action | Confirmation copy |
|--------|-------------------|
| **Stop sharing** (`alert-dialog`, destructive-toned confirm) | Title: "Stop sharing your location?" — Body: "Your last point stays visible until your time box runs out, then it's gone. You can't remove it sooner." — Confirm: **Stop sharing** (destructive). Cancel: **Keep sharing**. |

> There is **no Delete action** for a beacon — the substrate is no-delete and the lifecycle is expiry-driven (D-06). Stop is the only teardown verb, and it is consent-gated, not a delete.

**Three-clock legibility rule:** the running banner and view panel NEVER show `created_at`, `expiration`, and the time box as three equal-weight raw fields. Hierarchy: last-seen age (from `created_at`) is the primary "is this current?" signal; the countdown (from `expiration`) is secondary; the time box is only seen once, at Start, as a friendly preset.

## Net-New Surface Specs (concrete — no Phase-10/11 twin)

### 1. Beacons rail tab + BeaconsPanel (D-12)
- Add a **`beacons`** entry to `AppSidebar` `RAIL_DESTINATIONS` (`WORK_VIEW_MODES`) mirroring `sightings` — lucide icon **`Radio`** (or `Navigation`/`MapPin`-with-signal motif; `Radio` reads as "broadcasting presence", distinct from the Sighting `Eye`). Title: "Beacons".
- `BeaconsPanel` clones `SightingsPanelContent`: subscribes to kind-37521 (the discoverable surface) via a `useBeacons()` hook that `isLiveBeacon`-filters BEFORE cast AND `dropExpired`s at the subscription. Rows render the live/stale/ended status chip + last-seen age + countdown + a **Watch on map** action.
- The **user's own active beacon pins to the TOP** of the panel as a distinct card (accent-ringed when live) with its inline **Stop sharing** + **Adjust** — so "am I live?" is answerable from the index even if the map banner is scrolled away.
- Accent **Share live location** button at the panel top (the create entry → opens the control panel). Skeleton on load; the empty states from the copy table.
- **Mobile:** the panel is the existing collapsible single-column side panel; rows are full-width, the status chip + age sit on one line, actions wrap to a ≥44px action row beneath.

### 2. Start-beacon control panel (D-01/D-02/D-03/D-05/D-06/D-10)
- Opens in the info-panel slot (clone the Sighting editor slot) when **Share live location** is pressed. Single column, `space-y-6` between the four blocks: **time box → visibility → identity → consent + Start**.
- **Time box:** a `radio-group` rendered as a **2×2 preset grid** (mobile) / inline row (desktop); each chip ≥44px tall on mobile; selected chip carries the accent ring (reserved-accent #2). `Custom…` reveals a minutes/hours input. Default **1 hour** visibly pre-selected.
- **Visibility:** a `radio-group` of two cards (**Public** / **Link only**), asked every time, **no pre-selection persisted across sessions** (D-10). Selecting **Link only** reveals the non-dismissible honesty caveat inline beneath it (not a tooltip, not an accordion — always visible once link-only is chosen).
- **Identity:** a `radio-group` (**Anonymous** default / **My account** opt-in). Choosing **My account** swaps the consent block to its stronger-weighted copy.
- **Consent + Start:** the no-delete consent copy sits directly above the **Start beacon** button (accent, `h-12` full-width on mobile, bottom-anchored in the panel's thumb zone). Pressing Start IS the consent — there is no separate checkbox to mis-tap, but the copy is always on screen above the button.
- **Permission gate:** if location permission is not yet granted, Start is disabled and shows the permission-denied/needed copy; granting re-enables it.

### 3. Running-beacon status surface (the always-on "you are live" banner) — MOBILE-CRITICAL
- While a beacon is live, a **persistent `.glass-panel` banner/pill is pinned over the map**, visible at all times regardless of which panel is open or scrolled. The map stays the canvas; this banner is the one piece of always-on chrome.
- **Mobile:** bottom-anchored, full-width, inside the safe-area inset (above any bottom nav), in the thumb zone — `LIVE` status word (12px semibold) + "ends in {countdown}" + an unmistakable **Stop sharing** button (≥44px, destructive-toned) on the trailing edge. One tap from Stop at all times.
- **Desktop:** a compact pill in a map corner (e.g. top-center or bottom-center) with the same three elements.
- Sub-states: when location is searching/unavailable mid-session, the banner shows a "searching…" sub-line (copy table) rather than disappearing — the user must never silently lose the "I am live" signal.
- Color: neutral `.glass-panel` surface; the `LIVE` word + a small dot use `--primary`; Stop uses destructive tone. Reduced-motion: the live dot is static (no pulse) under `prefers-reduced-motion`.

### 4. Beacon view / detail panel (D-09 discretion)
- Clone `SightingViewPanel`: `EntityPanelShell` + a tone surface showing the **label** (20px), **live/stale/ended status chip**, **last-seen age** (primary), **time-box countdown** (secondary), and the **Copy share link** affordance.
- Owner viewing their own live beacon also sees inline **Stop sharing** + **Adjust** here (redundant with the banner by design — discoverable from the detail too).
- Comment/react mount: mount the existing `CommentsPanel` + `GeoSocialActions` on the 37521 coordinate IF cheaply reused (D-09 "if cheaply reused") — same pattern as Story/Sighting; planner may defer if the throwaway-key author makes comment-rooting awkward.
- Three-clock legibility rule applies — no raw epoch fields.

### 5. Live / stale / ended map marker (D-07/D-08)
- A distinct beacon marker rides the existing `useMapLayers` source/layer pattern (mirror the Sighting circle+glyph pair) with its own `dropExpired`-before-source-build, re-evaluated on every map tick so staleness flips and expiry-removal happen live.
- Glyph: a **broadcast/signal** motif (a dot with concentric rings, or lucide `Radio`/`RadioTower` in a marker), NOT the Sighting `Eye` and NOT a plain dataset circle — it must read as "live presence."
- Paint is data-driven on a `beaconState: 'live' | 'stale' | 'ended'` property using the hex + opacity in the Color table. The **live** marker is the canvas focal point (the single accent-colored, pulsing element); stale/ended recede to neutral grey.
- Each marker carries its "last seen Ns/m ago" / "ended Nm ago" label per the Color table. Touch hit target ≥44px (invisible padded layer).
- **Mobile legibility:** the live marker's ring + label must remain legible at typical mobile zoom with a finger partially over the screen — the label sits offset (above/leading) so a thumb on the dot doesn't cover the age. Stale markers are demoted but never invisible (BEACON-03 honesty).

### 6. /beacon/:naddr account-free share view + OG card (D-11)
- Mirror the Story/Sighting deep-link + OG pattern: add a `/beacon/:naddr` route to `useRouting` (a thin per-kind clone — Phase 13 / XCUT-02 owns generalization; flag at plan time) and an OG crawler match in `src/lib/og/`.
- The link MUST carry the **throwaway pubkey** for the default anonymous beacon (it is not discoverable under the user's profile). Opens without an account (guest scope already exists).
- The viewer lands on the map focused on the beacon, with the view panel open showing label + live/stale/ended status + last-seen age + countdown. If the beacon has ended/expired, the "This beacon has ended." terminal copy shows instead of a live dot.
- OG card: reuse the audited `generateOGHtml` escaping; show label + "Live location" + a static map/state snapshot. Since the beacon may already be stale/ended when the card is fetched, the OG copy is honest ("Live location — may have ended").

## Responsiveness & Accessibility

- **Mobile-first / collapsible panels** (CLAUDE.md): the Beacons panel + control panel + view panel live in the existing collapsible side-panel system; single-column at all widths. The running-beacon banner is bottom-anchored and safe-area-inset on mobile, corner-pill on desktop.
- **Touch targets:** Start/Stop ≥48px (`h-12`) on mobile; Stop-in-banner, marker hit area, preset chips, and all icon-only controls ≥44px. Icons stay 14–16px inside the padded targets.
- **One-handed reachability:** primary Start submit and the running-banner Stop are bottom-anchored in the thumb zone on mobile.
- **Color is never the only signal:** live/stale/ended differ by **status-word text** (LIVE / STALE / ENDED) and **marker shape** (solid / faded / hollow), not only color; the link-only caveat is **text**, not a color cue; Stop's consequence is **words**, not only the destructive tint.
- **Keyboard:** preset/visibility/identity radio-groups, Start/Stop, Copy-share-link, and the Stop `alert-dialog` are keyboard-reachable with visible focus rings (`outline-ring/50`, global).
- **Reduced motion:** the live-marker pulse halo and the banner live-dot are static under `prefers-reduced-motion`; map fly-to on opening a beacon jumps rather than animates.
- **Honest staleness (BEACON-03):** a beacon whose updates stopped (tab closed) flips to **STALE** within the threshold (D-08 — a tight multiple of the heartbeat, intent: a couple of minutes) and is NEVER painted as live; the last-seen age is always truthful. The view never shows a frozen old position as "live."
- **XSS posture:** beacon `label` renders as an auto-escaped React text node — no `dangerouslySetInnerHTML`.
