<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay → StoryViewPanel narrative | An untrusted kind-37520 Markdown body (possibly attacker-authored) is rendered to the reader |
| body naddr refs → main-map render | Inline naddr refs point at attacker-controllable target events (datasets) that may be offline/deleted/forged |
| relay → OG crawler (handleStoryRoute) | An untrusted Story's title/summary/image is embedded into server-rendered OG HTML served to crawlers |
| reader → comment/react | Untrusted comment text is posted against the Story coordinate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-07 | Elevation of Privilege (XSS) | StoryViewPanel narrative render | mitigate | Body renders ONLY through the sanitized `RichContentRenderer` — NIP-23 Markdown + the fixed inline ref/media extension set, no `dangerouslySetInnerHTML`, no raw HTML (REQUIREMENTS "Out of Scope: free-form WYSIWYG / arbitrary HTML"; UI-SPEC XSS posture); grep gate asserts 0 dangerouslySetInnerHTML |
| T-10-08 | Tampering / Information Disclosure | inline naddr refs → main map | mitigate | Malformed naddr refs render as inert plain text (excluded from `a`, naddrToCoordinate→null); refs default HIDDEN on load (reader opts each in — UI-SPEC §2), so opening a Story never auto-loads attacker-controlled targets; an unresolvable target shows "This reference couldn't be loaded…" rather than breaking |
| T-10-09 | Elevation of Privilege (XSS) | handleStoryRoute OG HTML | mitigate | generateStoryOGHtml copies the existing generateGeoEventOGHtml/generateContextOGHtml escaping path (same OGMeta template that already serves untrusted dataset/context titles); no new escaping logic invented — reuse the audited template |
| T-10-10 | Spoofing | comment/react on Story coordinate | accept | Comments/reactions reuse the shipped NIP-22/kind-7 path (proven on Groups Phase 9); authorship is established by the reader's own signature; no new trust surface vs the existing comment system |
| T-10-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies; no @mapcn block consumed (UI-SPEC Registry Safety); lucide BookOpen icon is already in the installed lucide-react |
</threat_model>
