<objective>
Deliver STORY-06: a reader proposes an edit to a Story's narrative (a kind-37519 proposal
carrying the proposed Markdown body) and the author previews a diff and accepts (republish in
place) or rejects. This generalizes the existing dataset proposal machinery
(`geo-proposal/` + `social/proposals/`) to a Markdown-content target.

**Spec-discriminator decision (resolved here, citing SPEC.md):** The kind-37519 generalization
is a **PURE CONTENT-TYPE EXTENSION — NO spec discriminator tag is needed.** Rationale:
(1) SPEC.md §11.1 defines the 37519 `content` field as a free-form `JSON.stringify(...)` string
with no content-type tag; the field is already untyped at the protocol level. (2) The proposal's
`a` tag already disambiguates the target kind — `37520:owner:d` for a Story vs `37515:owner:d`
for a dataset (SPEC.md §11.2 + §17 "Coordinates in the form `<kind>:<pubkey>:<d>` remain the
canonical reference target"). A consumer reads the target kind from the `a` coordinate and
parses `content` accordingly (Markdown for 37520, FeatureCollection for 37515) — no on-event
discriminator required. (3) The existing dataset path is untouched (`GeoProposalFactory.create`
+ `useGeoProposals` stay dataset-specific); we add a parallel Story path, honoring the roadmap's
"amend, don't replace" decision. This is recorded in the SUMMARY and is the answer to the
ROADMAP/CONTEXT open question.

Purpose: Close the last STORY requirement by reuse + a thin content-type generalization, with
accept routing through the Plan-01 `editStory` path so the body's `a` tags re-derive correctly.
Output: a Story-proposal factory method + helper, a `useStoryProposals` hook, the author panel
+ reader dialog, and the StoryViewPanel mount.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted reader → kind-37519 proposal | Any reader can submit a proposal carrying arbitrary Markdown targeting another user's Story |
| proposal content → author accept-preview | The author previews and may accept attacker-authored Markdown that then becomes their published Story body |
| proposal `a` coordinate → target-kind dispatch | The target kind is read from an attacker-influenced `a` coordinate string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-11 | Elevation of Privilege (XSS) | StoryProposalsPanel accept-preview | mitigate | The proposed Markdown MUST pass the SAME sanitized `RichContentRenderer` path before the author accepts (no `dangerouslySetInnerHTML`, no raw HTML) — the proposal preview is exactly as XSS-safe as the live narrative; grep gate asserts 0 dangerouslySetInnerHTML in both proposal files |
| T-10-12 | Tampering | accept → republish | mitigate | acceptStoryProposal republishes via the Plan-01 `editStory` path, so the accepted body's `a` tags are re-derived from the body (STORY-03) and the d-tag lineage is preserved (STORY-04) — an accepted proposal cannot inject phantom `a` tags or fork the lineage; the published content is the previewed-and-sanitized Markdown |
| T-10-13 | Spoofing / target confusion | getProposalTargetKind off the `a` coordinate | mitigate | Target kind is parsed from the `a` coordinate (kind:pubkey:d) and used to pick the parser (Markdown for 37520, FC for 37515); a malformed/forged coordinate yields no valid target and the proposal is not actionable — no cross-kind content confusion (the no-discriminator decision relies on this disambiguation, SPEC.md §17) |
| T-10-14 | Denial of Service | useStoryProposals over relay proposals | mitigate | Proposal events are subscribed by `#a` coordinate + kind 37519 and read defensively (getProposalMarkdownContent returns a string, never throws); a malformed proposal renders inertly, consistent with the never-throw-in-list-map discipline (SPEC.md §16.4) |
| T-10-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies (diff preview reuses RichContentRenderer + existing dialog/alert/badge); no @mapcn block consumed |
</threat_model>
