# Phase 10 — UI Design Contract

> Visual and interaction contract for the Story / Article (kind ~37520, NIP-23) frontend surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance posture:** This phase ADDS new panels (`StoryEditorPanel`, `StoryViewPanel`) and a `StoriesPanel` browse destination, but it is **reuse-dominant** — the data layer (`ArticleFactory`/cast/helpers), the TipTap editor stack (`GeoRichTextEditor` + `GeoMentionExtension` + `RichContentRenderer` + `MediaExtensions` + `contentParser`, which already render inline geo-refs with eye-toggle + fly-to in comments), the proposal machinery (`geo-proposal/` + `social/proposals/`), the comment/react surface (`CommentsPanel` + `GeoSocialActions`), and the panel primitives (`EntityPanelShell` / `EntityPanelSurface` / `EntityPanelSectionHeader` / `EntityActionBar` / `ConfirmDeleteAction`) all already exist. Spacing, color, and typography are **inherited from the shipped app design system** (`styles/globals.css` oklch tokens, Poppins, the `rounded-none` convention). This contract expresses only the deltas the Story authoring/reading surfaces add — it does NOT invent a new look & feel, and it stays consistent with the Phase 9 (Group) contract.

## Spacing Scale

The app's base unit is **4px** (`--spacing: 0.25rem`). Panels are dense (`text-[13px]` bodies, `py-2` rows). Declared scale (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|--------------------|
| 2xs | 4px | Inline status-chip padding (`py-0.5`), icon-to-label gaps (`gap-1`), eyebrow-to-title gap, eye-toggle/fly-to icon gap |
| xs | 8px | Compact element spacing (`gap-2`, `space-y-2`); Story list-row vertical padding (`py-2`); chip horizontal padding (`px-2`); editor field stack |
| md | 16px | Comment/discussion block stack (`space-y-4`); editor section stack; cover-image-to-title gap |
| lg | 24px | Gap between major editor sections (metadata block ↔ body editor ↔ proposal area) |
| xl | 32px | Reserved — not needed inside the width-constrained info-panel column |
| 2xl | 48px | Reserved |
| 3xl | 64px | Reserved |

The declared scale uses only standard-set values {4, 8, 16, 24, 32, 48, 64}.

**Exceptions (tolerated inherited values — not part of the new declared scale):**
- **Inherited panel rhythm (12px):** the section inner stack (`space-y-3`) and toned-surface inner padding (`px-3 py-3`) are inherited verbatim from the existing Group/dataset panels and the comment surfaces. 12px is NOT a declared scale value; it is a tolerated inherited-panel-rhythm exception. New surfaces this phase introduces use the declared scale; reused surfaces keep their rhythm as-is.
- **Inherited prose rhythm inside `RichContentRenderer`:** the Markdown narrative's paragraph/heading vertical rhythm is governed by the existing renderer's typography classes (comment parity) — do NOT re-style it per-Story.
- **Touch targets:** icon-only controls (the per-inline-ref **eye-toggle** + **fly-to** buttons, the per-Story ⋮ overflow, `EntityActionBar` buttons) render at the existing compact `h-6`/`h-7` (24–28px) inside the desktop side panel. On the mobile collapsible-panel breakpoint, the ⋮ overflow, the **New Story** button, and the inline eye-toggle/fly-to controls MUST present a **≥44px** hit area (pad the trigger; icon stays 14–16px).

## Typography

Inherited from `EntityPanelShell` + the existing panels and `RichContentRenderer`. Poppins throughout; JetBrains Mono only for raw `naddr`/coordinate strings. Exactly 4 sizes, 2 weights.

The declared scale is exactly 4 sizes (20, 14, 13, 11) and 2 weights (400, 600):

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Display (panel title) | 20px (`text-xl`) | 600 (semibold), tracking `-0.03em` | 1.2 | `StoryEditorPanel` / `StoryViewPanel` top title via `EntityPanelShell`; the Story's own rendered `# title` heading |
| Heading (section title) | 14px (`text-sm`) | 600 (semibold), tracking `-0.02em` | 1.3 | `EntityPanelSectionHeader` titles; Story list-row title; "Discussion" / "Proposed edits" section titles |
| Body | 13px (`text-[13px]`) | 400 (regular) | 1.5 (`leading-5`) | Summary text, Story list-row meta, narrative body paragraphs (via `RichContentRenderer`), proposal diff text |
| Label / meta | 11px (`text-[11px]`) | 400, eyebrows 600 uppercase tracking `0.2em` | 1.4 | Field labels, status chips (Draft/Published), author/date meta, `naddr` ref labels, eyebrows |

**Tolerated inherited sizes — NOT part of the new declared scale:**
- **12px (`text-xs`):** appears in reused surfaces (comment meta, list-row secondary text, the raw-`naddr` mono strings) carried over from the existing panels/comments. Tolerated inherited value, not a declared scale size; new copy this phase introduces uses the declared 13px body / 11px meta.
- **10px (`text-[10px]`):** dense inherited chips/coordinate strings in `RichContentRenderer` / comment chrome. Same posture — tolerated, not part of the declared scale.

**Weights:** regular (400) and semibold (600) only. Legacy `font-medium` (500) in reused code is tolerated as inherited; new copy uses 400/600.

**Monospace:** rendered `nostr:naddr…` reference tokens and the optional raw-Markdown-source `Textarea` (if the planner picks a Markdown-source editor over TipTap) use `font-mono text-xs` (existing convention).

## Color

Inherited oklch tokens (`styles/globals.css`). Light + dark both defined; use **semantic tokens only** (`bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `border-border`, `bg-primary`, `bg-destructive`) — never raw `dark:` literals for semantic color.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` (near-white light / near-black dark) + `.glass-panel` surface | Panel canvas, Story list rows, cover-image frame, narrative reading surface |
| Secondary (30%) | `--muted` / `--muted-foreground` / `--border` (neutral greys) | Section dividers, meta text (author/date), chip borders, disabled controls, draft chrome, inline-ref inactive (hidden-on-map) state |
| Accent (10%) | `--primary` (warm amber/gold `oklch(0.85 0.17 88)`) | Reserved list below |
| Secondary semantic | `--secondary` (cyan/blue `oklch(0.75 0.16 233)`) | The **"shown on map"** active state of an inline geo-ref (eye-toggle ON) and the "Published" status badge ONLY (see below) |
| Destructive | `--destructive` (red) | Delete Story; Discard draft; Reject proposal — never for status or warnings |

**Accent (`--primary`) reserved EXCLUSIVELY for:**
1. The **New Story** primary button at the top of the Stories rail panel (D-02).
2. The editor primary submit button (**Publish Story** / **Save changes**).
3. The **Accept** action on a previewed narrative edit proposal (STORY-06) — the one constructive commit.
Nothing else. Section eyebrows, meta, counts, author lines, inactive inline-ref controls, and the **fly-to** button stay neutral (`muted-foreground`).

**Inline geo-ref state encoding (STORY-02, load-bearing — color is never the only signal):**
- **Shown on map** (eye-toggle ON): eye icon filled, ref token gets the `--secondary` (cyan) accent ring/tint + an "open eye" icon. This is a *state*, not a CTA — distinct from `--primary`.
- **Hidden on map** (eye-toggle OFF, the safe default on load — see Interaction §2): eye icon "crossed/closed", ref token neutral (`muted-foreground`, `border-border`).
- **Fly-to** is always neutral (a navigation affordance, not a state) — `muted-foreground` icon button with a tooltip.

**Status / lifecycle colors (badges):**
- **Draft** → neutral `Badge variant="outline"` (`muted-foreground`) — a draft is unpublished, quiet, never accented.
- **Published** → `Badge variant="secondary"` (`--secondary`).
- **Edit proposed** (a Story with a pending kind-37519 narrative proposal, author's view) → amber `Alert variant="default"` banner (NOT destructive — a proposal is an invitation, not an error).

Dark-mode parity: every chip/badge/alert/cover-frame MUST use token-driven classes so the dark palette applies automatically. Avoid hard-coded `text-slate-*`/`bg-white` for new copy; prefer `text-foreground` / `text-muted-foreground` / `bg-card`.

| Situation | Copy (problem → what to do) |
|-----------|------------------------------|

| Proposal couldn't be applied/previewed | Couldn't load this proposed edit. Ask the author to re-send, or try again. |
| Inline `naddr` ref is malformed | This reference isn't valid and won't appear on the map. (the ref renders as plain text, not a broken token) |

## Interaction Contracts (phase-specific surfaces)

These are the load-bearing interaction specs the executor implements. Each cites its decision/requirement.

### 1. Stories browse rail + create entry (D-01 / D-02)
- A dedicated **Stories** destination is added to `AppSidebar`'s `RAIL_DESTINATIONS` (alongside Datasets/Contexts), opening a `StoriesPanel` that follows the `GeoDatasetsPanelContent` browse pattern (list rows, search/filter, recency).
- A **New Story** primary button (`--primary`) sits at the **top of the Stories panel** (mirrors the Datasets/Groups create affordance). Create + browse stay co-located. This explicitly closes the Phase-9 discoverability gap (a built-but-unwired table that dead-ended at "No Group selected").
- Each list row: cover thumbnail (or neutral placeholder) + title (14px semibold) + summary one-liner (13px `muted-foreground`, truncated) + author/date meta (11px) + a **Draft**/**Published** status chip + a ⋮ overflow (`dropdown-menu`). Loading uses `skeleton` rows.

### 2. Open layout & the "map lane from the body" (D-03)
- An opened Story renders in the **right info panel** via `GeoEditorInfoPanel` view multiplexing (like Groups/datasets) — `StoryViewPanel`. The **main map stays the canvas**; there is NO takeover reading view this phase (deferred).
- The "map lane derived from the body" = the **main map filtered to the Story's referenced features**, driven by the inline eye-toggles — not a separate map widget.
- **Inline refs default to HIDDEN on load** (eye-toggle OFF): opening a Story must not dump every referenced dataset onto the map at once. The reader opts each ref in. (Planner may revisit; default-hidden is the safe, decluttered default per CONTEXT "whether inline refs default shown or hidden on load" discretion.)
- Each inline geo-ref token (rendered by `RichContentRenderer`, reusing the comment inline-ref machinery) carries: an **eye-toggle** (Show on map / Hide from map; `--secondary` tint when ON) and a **fly-to** button (neutral). Tooltips per the copy table. Reuse `contentParser` + the existing mention render — do NOT build a new inline-ref renderer.

### 3. Body authoring + geo-ref insertion (STORY-01/02, Claude's-discretion → reuse)
- **Editor type (discretion):** prefer reusing the TipTap `GeoRichTextEditor` if Markdown serialization is clean; otherwise a raw Markdown-source `Textarea` + **Preview** tab is acceptable. **Stored `content` MUST be Markdown (NIP-23)** either way. The contract is agnostic to which the planner picks, but the **Write / Preview** tab pair and the `@`-mention insertion below are required in both.
- **Geo-ref insertion (discretion default):** reuse the existing `@`-mention picker (`GeoMentionExtension` + `command`/`popover`) to search datasets/features and insert a `nostr:naddr…` reference inline. Same picker covers image/video embeds via `MediaExtensions`.
- Metadata block above the body: **Title** (`input`), **Summary** (`textarea`), **Cover image** (upload/URL with a 16:9 `aspect-ratio` preview). These map to NIP-23 `title`/`summary`/`image` tags via `ArticleFactory`.

### 4. naddr → `a` mirroring (STORY-03) — invisible-but-honest
- On every publish, `a` tags are **re-derived from the Markdown body's `nostr:naddr…` refs** (`extractNostrAddressReferences` → `dedupeNostrAddressReferences` → `naddrToCoordinate` → `setReferencedAddresses`). Single source of truth = the body; `a` tags are never hand-edited.
- This is silent (no UI surface) EXCEPT: if a ref in the body is malformed, it renders as plain text and is excluded from `a` (copy: "This reference isn't valid…"). No phantom UI for the `a`-tag list — refs live in the prose.

### 5. Draft + in-place edit (STORY-04)
- **Draft storage (discretion default):** local-first — mirror the editor's `writePersistedGeoCollectionDraftState` draft pattern (local-only until publish). A **Save draft** button persists locally; a **Draft** status chip marks unpublished Stories. (A NIP-23 kind-30024 draft event is an acceptable alternative the planner may choose; local-first preferred for simplicity.)
- **Edit in place:** editing a published Story preserves the same **`d`-tag lineage** (parameterized-replaceable), exactly like `GroupFactory.modify`. The editor opens pre-filled; submit is **Save changes**, not a new publish.
- **Discard draft** is destructive-confirmed (copy table).

### 6. Comment + react (STORY-05) — a mount, not new infra
- `StoryViewPanel` mounts the existing `CommentsPanel` + `GeoSocialActions` on the Story's 37520 coordinate (kind 37517 comments + kind 7 reactions), exactly as Phase 9 mounted them on Groups. Either a **Discussion** tab or a below-narrative section — planner's call; both reuse the same components with zero new comment UI.

### 7. Propose narrative edit (STORY-06) — reuse proposal machinery
- A reader sees a **Propose an edit** action on a published Story; it opens the body in an edit affordance and submits a **kind-37519 proposal targeting the Story's Markdown content** (reuse `geo-proposal/` factory/cast + `social/proposals/` UI — `ProposalCard` / `ProposalsPanel`).
- The author sees a **Proposed edits** section (amber `Alert` banner when pending) listing proposals; **Review edit** opens a **preview with a diff** of the proposed narrative vs current. Accent **Accept edit** republishes in place (same `d`-tag); destructive-toned **Reject** dismisses.
- **Open question to resolve at planning (flagged in CONTEXT):** whether the 37519 generalization to a Markdown-content target is a pure content-type extension or needs a spec discriminator. The UI contract above holds regardless; the executor confirms the data shape during planning.

## Responsiveness & Accessibility

- **Mobile-first / collapsible panels** (per CLAUDE.md): the Story panels live in the existing collapsible side-panel system; single-column at all widths. On small screens the ⋮ overflow, **New Story** button, and inline eye-toggle/fly-to controls get a **≥44px** hit area (icon stays 14–16px).
- **Keyboard:** the `@`-mention picker, editor tabs, eye-toggle/fly-to buttons, and the ⋮ menu are all keyboard-reachable with visible focus rings (`outline-ring/50`, global). Inline-ref tokens are focusable buttons, not bare spans.
- **Reduced motion:** fly-to map camera animation and Dialog/Alert/Collapsible animations respect the global `@media (prefers-reduced-motion)` rule in `index.css` (fly-to should jump rather than animate under reduced-motion).
- **Color is never the only signal:** inline-ref "shown on map" state shows a filled/open-eye **icon** (not only the `--secondary` tint); Draft vs Published differ by **label text**, not only chip color; a proposed-edit banner carries text, not only amber.
- **Markdown narrative (STORY-01) — XSS posture:** the body renders ONLY through the app's existing **sanitized `RichContentRenderer`** (no `dangerouslySetInnerHTML`, no raw HTML — NIP-23 Markdown + the fixed inline ref/media extension set only, per REQUIREMENTS "Out of Scope: Free-form WYSIWYG / arbitrary HTML"). This matches the Group narrative posture from Phase 9.
- **Images/video:** embedded media uses `aspect-ratio` to reserve space (no layout shift) and lazy-loads; cover image falls back to a neutral placeholder on error.
