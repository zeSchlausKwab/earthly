<objective>
Ship the off-thread schema-validation Web Worker (SPEC-04) — the one genuinely new trust boundary this phase introduces. An Ajv schema fetched from a relay is stranger-authored executable input (ReDoS `pattern`, recursive/external `$ref`, oversized/deep OOM). The worker hardens it: off-thread, hard timeout-kill (≤100ms + slack), fail-closed, `$ref`/`$dynamicRef` rejected before compile, byte-size/depth/keyword caps, `$data` off, `ajv/dist/2020` pinned, compile-once-per-`schemaHash` cache, plus a synchronous fallback so the hardening is unit-testable without a live `Worker`.

Purpose: Land the hardened worker + a typed `validateSchema()` call interface. Phase 9 wires it into the Group validate-on-fetch pipeline; Phase 8 ships the worker + interface ONLY (no Group wiring).
Output: `schema.worker.ts` (pure engine), `schemaWorker.ts` (client harness), and the mandatory `workerAssets.ts` registration entry.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay → schema worker | An Ajv schema authored by a stranger and fetched from a relay is untrusted executable input crossing into the validator. This is the one new boundary Phase 8 introduces. |
| worker registry → runtime | The worker artifact must actually emit and be served, or the safety guarantee silently degrades to fail-open. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04-RD | Denial of Service | ReDoS `pattern` (CVE-2025-69873 class) in an untrusted schema, validated against a long input | mitigate | Off-thread + host watchdog `terminate()` on overrun (≤100ms in-engine + 500ms wall-clock slack) → fail-closed "could not validate"; `ajv@8.20.0` carries the ReDoS patch. Asserted by the timing-bounded `schemaWorker.test.ts` rows. |
| T-08-04-REF | Denial of Service | Recursive/external `$ref`/`$dynamicRef` resolver blowup | mitigate | `rejectUnsafeSchema` rejects any `$ref`/`$dynamicRef` BEFORE `ajv.compile`; external `$ref` never resolves. |
| T-08-04-OOM | Denial of Service | Oversized / deeply-nested schema OOM | mitigate | Byte-size (`MAX_SCHEMA_BYTES`), depth (`MAX_DEPTH`), and keyword-count caps enforced before compile. |
| T-08-04-PP | Tampering | Prototype pollution via `format` + `$data` | mitigate | `$data` OFF (default kept; no `$data:true`); `ajv` 8.19.0+ proto-pollution patch; `format` is annotation-only by default. |
| T-08-04-SPOOF | Spoofing (of safety guarantee) | Worker never loads → validation silently no-ops (fail-OPEN) — the exact Phase 4 UAT blocker | mitigate | Registration via `workerAssets.ts` (single touchpoint) + `bun run build` gate proving emission; the fallback is fail-CLOSED, not fail-open; forbidden `new Worker(new URL(...))` form is absent. |
